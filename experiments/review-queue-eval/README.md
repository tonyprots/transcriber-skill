# Очередь проверки: сколько ошибок она ловит

Скрипт для таблицы «Зачем это нужно, в цифрах» из корневого README.
Прогоняет скилл в `fast` и `max` по размеченным записям и
считает не только WER, но и главное: какая доля ошибок распознавания
оказалась внутри окон, отмеченных в `review-needed.md`.

```bash
# 1. прогнать скилл по списку записей (id \t путь) в оба режима
while IFS=$'\t' read -r id audio; do
  for mode in fast max; do
    .venv/bin/python skills/transcriber/scripts/transcribe.py "$audio" \
      --mode $mode --language ru --no-cache --quiet --output eval/runs/$mode/$id
  done
done < files.tsv

# 2. посчитать
python3 experiments/review-queue-eval/score.py eval gold.jsonl public-ids.jsonl
```

`gold.jsonl` — строки `{"id": ..., "gold": "эталонный текст"}`;
третий аргумент делит выборку на публичную и личную части по id.
Выборка автора (30 реплик MINDS-14 ru-RU и 10 личных голосовых) в
репозиторий не входит.

Словарь из четырёх терминов, собранный из очереди проверки первого прогона
(`skills/transcriber/scripts/glossary_candidates.py`), дал WER 5,3 % вместо
6,7 %; сам словарь личный и в репозиторий не входит.

## Вторая выборка: диктовки

8 записей по 45 с – 3 мин, 42 окна, 1 274 слова эталона. Прогон в `max`,
затем `build_review.py EVAL_DIR` строит `review.html`: карточка на окно,
кнопка играет только это окно, в поле уже стоит текст GigaAM, рядом Whisper.
Экспорт — JSONL `{id: "<запись>#<окно>", gold}`; эталон записи — склейка
окон по порядку. Разметка 42 окон заняла около получаса.
Словарь из 13 терминов очереди первого прогона (личный, не в репозитории).
Итог: GigaAM 7,0 %, Whisper 13,6 %, скилл 5,8 %, со словарём 4,2 %;
`max` отмечает все окна и накрывает 100 % ошибок при точности отметки 74 %.
Прежний `balanced` (отбор рискованных окон, убран в 0.6.0) отмечал 71 % окон
и накрывал 78 % ошибок.
