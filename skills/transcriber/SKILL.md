# Локальная расшифровка аудио

Делай расшифровку воспроизводимо: сохраняй обе исходные гипотезы, отдельно читаемый результат, список автоматических исправлений и очередь спорных мест. Не выдавай отредактированный текст за дословный.

## Подготовить окружение

Определи каталог скилла как `SKILL_DIR`, **разрешив симлинки**: скилл может быть подключён ссылкой из репозитория, и тогда его `.venv` лежит не рядом, а в корне репозитория, на два уровня выше. Системный `python3` не годится: в нём нет `mlx_audio`, и проверочная модель тихо отвалится, а `max` выродится в `fast`.

```bash
SKILL_DIR="$(cd "$(dirname "$(readlink -f "$SKILL_DIR/SKILL.md")")" && pwd)"
for candidate in "$SKILL_DIR/.venv" "$SKILL_DIR/../../.venv"; do
  if [ -x "$candidate/bin/python" ]; then ASR_PYTHON="$candidate/bin/python"; break; fi
done
```

Если `ASR_PYTHON` не нашёлся, окружения ещё нет. Скажи пользователю, что установка займёт несколько минут, около 1 ГБ на пакеты и 2,5 ГБ на модели, и после его согласия выполни:

```bash
bash "$SKILL_DIR/scripts/setup.sh" --models ru   # .venv, зависимости и модели русского маршрута
```

`--models en` или `--models all` берут модели для английского, `--diarize` добавляет Sortformer. Без `--models` модели подтянутся при первом запуске `transcribe.py`; скачать их отдельно можно через `"$ASR_PYTHON" "$SKILL_DIR/scripts/prefetch_models.py" ru`.

Скрипт заканчивается проверкой `scripts/doctor.py`: Python, ffmpeg, пакеты, какие модели уже в кэше. Его же запускай, когда что-то не работает: `"$ASR_PYTHON" "$SKILL_DIR/scripts/doctor.py"`.

Модели загружаются с Hugging Face при первом запуске и остаются в `~/.cache/huggingface`: русский — GigaAM v3 (0,9 ГБ) и Whisper Turbo (1,5 ГБ), английский — те же плюс GigaAM Multilingual (0,2 ГБ), диаризация — Sortformer (0,2 ГБ). Предупреди пользователя о размере перед первым прогоном. Если Hub недоступен, а модели уже скачаны, конвейер сам переходит в офлайн; `--offline` делает это принудительно.

Платформа: Whisper Turbo через MLX и диаризация работают только на macOS Apple Silicon. На Linux и Intel Whisper идёт через faster-whisper на CPU, заметно медленнее, а `--diarize` отказывает сразу с понятным текстом.

## Выбрать режим

- `max` (по умолчанию) — обе модели подтверждённого маршрута на каждом окне. Для русского основная GigaAM v3 E2E и проверяющий Whisper Turbo, для английского наоборот: Whisper Turbo и GigaAM Multilingual CTC int8. Для языков без локальной калибровки остаётся один Whisper и явное предупреждение.
- `fast` — один проход основной модели по общим VAD-окнам, без независимой проверки и без очереди расхождений. Для русского это GigaAM v3 E2E, для остальных языков — Whisper Turbo.

Если пользователь не указал режим, выбирай `max`: на реальной речи в очередь попадает 98–100% ошибок распознавания, и переслушивать нужно только отмеченные окна. `fast` — когда пользователю нужна скорость и он готов остаться без очереди: текст у режимов одинаковый, пишет его одна и та же модель. Ориентир на Apple M1 (замер 2026-09-06): `max` — от четверти до трети длительности записи с диаризацией или без, то есть час аудио за 15–20 минут; `fast` — 8% длительности; диаризация Sortformer добавляет 10–45 секунд на загрузку модели и дальше почти ничего. Для записи длиннее часа назови эту оценку заранее. Фактические времена стадий пишутся в `manifest.json` → `timings_seconds`.

Проверочная модель получает не те же окна, что основная. Whisper всегда доводит вход до 30 секунд, поэтому окно на секунду стоит почти столько же, сколько на двадцать, а диаризация нарезает окна с медианой 2,4 секунды. Поэтому для Whisper окна проверки склеиваются в длинные (`--verifier-window-seconds`, по умолчанию 24; `0` отключает), а текст раскладывается обратно по исходным окнам через пословные таймкоды. Для GigaAM-проверки на английском склейка не применяется: у неё нет пословных таймкодов.

Перед началом проверяется свободное место: временные WAV занимают примерно три длительности записи. При нехватке прогон падает сразу с понятным текстом, а не в середине распознавания.

Все тяжёлые модели запускаются последовательно в отдельных процессах. Watchdog останавливает процесс, который пять минут не завершил ни одного окна и ничего не написал в лог; загрузка модели с прогресс-баром зависанием не считается. Если отдельное окно вернуло пустой текст или ошибку, оно рекурсивно делится пополам максимум два раза; частично восстановленный результат всегда попадает в очередь проверки.

## Запустить

```bash
"$ASR_PYTHON" "$SKILL_DIR/scripts/transcribe.py" INPUT \
  --mode max \
  --language ru \
  --output OUTPUT_DIR
```

`OUTPUT_DIR` скрипт создаёт сам. Не делай `mkdir` заранее и ничего в него не клади: непустой каталог без `--overwrite` — отказ. Лог фонового запуска держи **рядом**, не внутри.

Ход работы идёт в stderr: этапы и счётчик окон, не чаще раза в 20 секунд. Отключается `--quiet`. В stdout только итоговый JSON с путём результата, так что `2>/dev/null` оставит машиночитаемый вывод. Запись длиннее пяти минут запускай в фоне и следи по логу:

```bash
"$ASR_PYTHON" "$SKILL_DIR/scripts/transcribe.py" INPUT \
  --mode max --language ru --output OUTPUT_DIR > OUTPUT_DIR.log 2>&1 &
```

На macOS нет GNU `timeout`; ограничивать прогон снаружи не надо — за зависанием следит встроенный watchdog.

Строка лога «Результат записан … Уборка временных файлов» значит, что каталог уже готов и его можно читать; JSON в stdout появится только после уборки. Антивирус, проверяющий каждую файловую операцию, временами растягивает создание и удаление сотен временных WAV до секунды на файл: VAD вместо 5 секунд занимает минуты, уборка тоже — это не зависание, watchdog такое не трогает.

При наличии предметного словаря добавь `--glossary PATH.yaml`. `--whisper-backend auto` выбирает MLX на Apple Silicon и CPU-fallback иначе; на сбой уже работающей MLX-модели fallback не срабатывает, ошибка возвращается как есть. Гипотезы кэшируются по хешу исходника, общим окнам, языковому маршруту и конфигурации в `~/.cache/transcriber`; для контрольного чистого прогона есть `--no-cache`. Не ставь `--overwrite` без необходимости: прежний результат при этом переносится в архивный каталог рядом.

Для интервью, встречи или явной просьбы разделить говорящих добавь `--diarize`. Если число участников известно, обязательно добавь `--expected-speakers N`: до четырёх голосов `auto` выберет Sortformer, от пяти — FluidAudio Offline Community-1. Те же VAD-окна режутся по сменам спикера и одинаково подаются обеим ASR. Перекрывающаяся речь получает несколько меток и не транскрибируется дважды. Для одного голосового `--diarize` не нужен.

FluidAudio включён в пакет как macOS arm64 бинарник (происхождение и контрольная сумма — в `third-party/fluidaudio/NOTICE.md`), а его CoreML-модели хранятся отдельно. Перед первым большим совещанием, получив разрешение пользователя на загрузку 34 МБ, выполни:

```bash
"$ASR_PYTHON" "$SKILL_DIR/scripts/setup_fluidaudio_models.py"
```

После этого большой локальный запуск выглядит так:

```bash
"$ASR_PYTHON" "$SKILL_DIR/scripts/transcribe.py" INPUT \
  --language ru --mode max --diarize --expected-speakers 6 \
  --output OUTPUT_DIR
```

Если число найденных голосов не совпало с ожидаемым, считай все speaker labels требующими проверки. На других платформах маршрут 5+ голосов пока недоступен; не подменяй его ограниченным Sortformer.

## Работать со словарём

Схема и пример лежат в [assets/glossary.example.yaml](assets/glossary.example.yaml).

1. Вноси каноническое написание и известные варианты распознавания.
2. Ставь `auto_apply: true` только для однозначной точной замены.
3. Нечёткие совпадения не исправляй автоматически: они попадают в `review-needed.md`.
4. Новую ошибку добавляй как alias только после проверки по аудио или явного подтверждения пользователя.
5. Не меняй `raw.json`: он является аудит-следом исходных гипотез.

Словарь пополняется из очереди проверки, и это штатный цикл, а не разовая настройка:

1. После первого прогона сними кандидатов: `"$ASR_PYTHON" "$SKILL_DIR/scripts/glossary_candidates.py" OUTPUT_DIR --glossary СЛОВАРЬ.yaml --output candidates.yaml` (несколько каталогов результата можно передать сразу; `--glossary` исключает уже известные записи). Кандидаты — расхождения, где проверяющая модель написала латиницей, а основная кириллицей, и кириллические ослышки, повторившиеся в трёх и более окнах.
2. Покажи список пользователю с таймкодами первого окна. Спорное прослушай (`review-needed.md` даёт интервал), однозначное подтверди у пользователя.
3. Подтверждённые записи перенеси в рабочий словарь с `auto_apply: true`, остальные оставь с `auto_apply: false` — они будут попадать в «Возможные термины» очереди, не меняя текст.
4. Прогони запись заново с `--glossary`: гипотезы берутся из кэша, пересчитываются только словарь и очередь. На реальной речи автора словарь из одного такого цикла снял WER с 6,3% до 4,9% на голосовых и с 5,8% до 4,2% на диктовках.

## Проверить результат

В каталоге результата обязательны:

- `verbatim.md` — лексическая гипотеза без редакторского сглаживания;
- `readable.md` — читаемая гипотеза без филлеров («э-э-э», «хмм») и с разрешёнными словарными исправлениями;
- `subtitles.srt` — субтитры по читаемым сегментам;
- `subtitles.vtt` — те же субтитры в WebVTT;
- `segments.json` — общие окна, обе гипотезы и решения сверки;
- `glossary-audit.json` — словарные исправления и предложения;
- `review-needed.md` — расхождения моделей и возможные термины;
- `raw.json` — все исходные гипотезы, исправления и предложения;
- `manifest.json` — модели, режим, источник, тайминги стадий и счётчики.

При `--diarize` дополнительно создаётся `speakers.json`: нормализованные интервалы говорящих, исходные интервалы модели, её параметры и лимит спикеров. Метки также появляются в Markdown и субтитрах.

Всегда просмотри `review-needed.md`. Для важных имён, чисел, отрицаний, адресов, аббревиатур и продуктовых терминов прослушай отмеченный интервал. Проверочная модель — независимый сигнал, но её вариант не становится правильным автоматически: на русском holdout GigaAM была точнее Whisper на восьми записях из десяти. При диаризации часть пунктов — краевые артефакты: слово на границе окна попало к соседу; такие расхождения видны по одному отличающемуся токену в начале или конце.

После расшифровки можно делать резюме, протокол, список решений или задачи, но используй для фактических утверждений проверенный `readable.md`; нерешённые фрагменты обозначай явно.
