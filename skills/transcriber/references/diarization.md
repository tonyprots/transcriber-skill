# Диаризация: запуск и имена

Читать, когда пользователю нужна расшифровка по голосам. Какие модели и почему —
[models.md](models.md), раздел «Диаризация».

Голоса делит FluidAudio Offline Community-1 (macOS arm64) при любом числе
участников. Если число известно, обязательно укажи `--expected-speakers N`:
оно уходит в модель подсказкой, и на записях вдвоём число голосов угадывается
в 95% случаев против 82% без неё. Без подсказки скилл сам снимает «призраков»:
голос, у которого меньше 5 секунд и меньше 3% речи, отдаётся соседней реплике.
Те же VAD-окна режутся по сменам спикера и одинаково подаются обеим ASR;
перекрывающаяся речь получает несколько меток и не транскрибируется дважды.

Против диаризации там, где нужны только факты, — замер 2026-09-20: на точность
текста она не влияет. Лишние 3–4 голоса на записях двух собеседников
(2026-09-22) давал Sortformer, который тогда стоял по умолчанию.

Слабое место FluidAudio — короткие реплики: из вставок собеседника длиной 1–3
секунды находится половина, короче секунды почти ни одной. Короткое «да» или
«угу» в чужой реплике — нормальная ошибка, а не сбой.

## Имена вместо «Спикер 1»

`--speaker-names 1=Антон,2=Мария` (`unknown=Зал` для неразмеченной речи). Кто
есть кто, обычно понятно только после чтения, поэтому чаще имена ставят в
готовую расшифровку, без пересчёта звука:

```bash
"$ASR_PYTHON" "$SKILL_DIR/scripts/rename_speakers.py" OUTPUT_DIR 1=Антон,2=Мария
```

Переписываются тексты и субтитры, имена запоминаются в манифесте, а метки в
`raw.json`, `segments.json` и `speakers.json` остаются номерами.

## Установка и другие платформы

FluidAudio — бинарник macOS arm64, собранный CI репозитория из закреплённого
коммита; `setup.sh` скачивает его из Release и ставит только при совпадении
суммы (происхождение и проверка — `third-party/fluidaudio/NOTICE.md`). Нет его в
`bin/macos-arm64/` — перезапусти `setup.sh`. CoreML-модели (35 МБ, закреплённая
ревизия) скачиваются сами при первом `--diarize`; с `--offline` их нужно
поставить заранее: `prefetch_models.py --diarize`.

```bash
"$ASR_PYTHON" "$SKILL_DIR/scripts/transcribe.py" INPUT \
  --mode max --diarize --expected-speakers 2 --output OUTPUT_DIR
```

Если число найденных голосов не совпало с ожидаемым, считай все метки спикеров
требующими проверки. Sortformer остаётся только по явному
`--diarization-backend sortformer` и только до четырёх голосов: на живых
записях он путает голоса в 4–5 раз чаще (models.md). На других платформах
диаризации нет.
